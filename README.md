## โครงสร้างระบบ

```
หน้าเว็บ Panolyzer (GitHub)
        │  GET  ?app=panolyzer  → ดึงข้อมูลทั้งหมด
        │  POST {action, data, adminPassword}
        ▼
Google Apps Script (Code.gs ตัวเดียวกับ Service Tracker / Color Sorter / C2-Loop)
        ▼
Google Sheets
  ├─ Panolyzer Data    ← เครื่องละ 1 แถว: สถานะ "ตอนนี้"
  └─ Machine_History   ← การทดลองละ 1 แถว: ประวัติ
```

ชีต **Panolyzer Data** ใช้ร่วมกับระบบอื่น:
- **Service Tracker** อ่านวันนัด PM และบันทึกการเข้า PM (`PM1_Status`–`PM3_Status`)
- **C2-Loop** เพิ่มเครื่องใหม่ผ่าน `AddMachine.gs`

## กฎการ sync (ประวัติ → ข้อมูลเครื่อง)

### 1) รายการไหน "กำหนดสถานะเครื่อง"

- ถ้ามีรายการ **กำลังทดลอง** → ใช้รายการนั้น
- ถ้าไม่มี → ใช้รายการที่ **วันเริ่มใหม่ที่สุด**
- **แก้หรือเพิ่มประวัติเก่าย้อนหลัง จะไม่กระทบข้อมูลเครื่อง**

### 2) รายการนั้นทำให้เครื่องเป็นอะไร

| ประวัติ | ข้อมูลเครื่อง |
|---|---|
| กำลังทดลอง | สถานะ **Test** + ลูกค้า + สถานที่ + Mode ตามที่ทดลอง |
| จบแล้ว + **ซื้อ** | สถานะ **Complete** + ลูกค้า/สถานที่ของรายการนี้ + **วันส่งมอบ = วันสิ้นสุดการทดลอง** + นัด PM1–3 ใหม่* |
| จบแล้ว + ไม่ซื้อ | สถานะ **Stock** + ล้างลูกค้า/สถานที่ |
| จบแล้ว + รอพิจารณา | สถานะ **Stock** + ล้างลูกค้า/สถานที่ |

\* นัด PM1 / PM2 / PM3 = วันส่งมอบ +4 / +8 / +12 เดือน **เฉพาะเครื่องที่ยังไม่เคยเข้า PM** (`PM1_Status`–`PM3_Status` ว่างทั้งหมด) ถ้าเคยเข้า PM แล้วเปลี่ยนแค่วันส่งมอบ ไม่ทับนัด PM เดิม

### 3) ช่องติ๊ก "อัปเดตข้อมูลเครื่องตามรายการนี้"

อยู่ในฟอร์ม **เพิ่มประวัติเอง / แก้ไขประวัติ** และหน้าต่าง **ลบประวัติ** ("ปรับข้อมูลเครื่องตามประวัติที่เหลือ")

- ติ๊กไว้ให้อัตโนมัติถ้ารายการนั้นเป็นรายการล่าสุด
- ถ้าเป็นประวัติเก่า ช่องจะจางและกดไม่ได้ (ไม่กระทบเครื่องอยู่แล้ว)
- **เอาติ๊กออก = บันทึกประวัติอย่างเดียว ไม่แตะข้อมูลเครื่อง**
- ปุ่ม **เริ่มทดลอง / ปิดการทดลอง** ไม่มีช่องติ๊ก (อัปเดตเครื่องเสมอ)

### 4) กล่องบอกผลล่วงหน้า (ก่อนกดบันทึก)

ทุกฟอร์มมีกล่องบอกว่า "ถ้าบันทึก ข้อมูลเครื่องจะเปลี่ยนอย่างไร" (สถานะ / ลูกค้า / สถานที่ / Mode / วันส่งมอบ / นัด PM แบบ ก่อน → หลัง)

| สีกล่อง | ความหมาย |
|---|---|
| 🔴 แดง | ควรตรวจก่อนกด: เครื่องขายแล้วจะกลายเป็นสถานะอื่น / ชื่อลูกค้าถูกเปลี่ยนหรือล้าง / วันส่งมอบหรือนัด PM ถูกทับ |
| 🟢 เขียว | ไม่มีผลกับข้อมูลเครื่อง (ข้อมูลตรงกันอยู่แล้ว) |
| ⚪ เทา | บันทึกประวัติอย่างเดียว หรือเป็นประวัติเก่า |
| 🟩 เขียวอ่อน | เปลี่ยนตามปกติ (เช่น ปิดการทดลอง) |

กล่องนี้ใช้กฎเดียวกับ Code.gs ทุกข้อ (ทดสอบเทียบกันแล้ว)

### 5) กรณีอื่น

- **เริ่มทดลองใหม่ขณะเครื่องยังทดลองค้างที่อื่น** → รายการเดิมถูกปิดเป็น "จบแล้ว / ไม่ซื้อ" (วันสิ้นสุด = วันนี้) อัตโนมัติ
- **ลบประวัติรายการล่าสุด** → ข้อมูลเครื่องปรับตามรายการที่เหลือ (ไม่แตะวันส่งมอบ) · ถ้าไม่เหลือประวัติและเครื่องเป็น Test → กลับ Stock
- **แก้วันส่งมอบ (หน้าแก้ข้อมูลเครื่อง หรือพิมพ์ในชีต)** → ถ้ายังไม่มีวันนัด PM1 ระบบคำนวณ PM1–3 ให้

## วิธีแก้เคส: ลูกค้าสลับไปซื้อเครื่องอื่น

ตัวอย่าง: เครื่อง A ลูกค้า 1 ทดลอง (รอพิจารณา) → ลูกค้า 2 ซื้อเครื่อง A ไป → ลูกค้า 1 ซื้อเครื่อง B แทน

1. **เครื่อง A · เพิ่มประวัติเอง** รายการลูกค้า 2: วันเริ่ม = วันสิ้นสุด = วันส่งมอบจริง · จบแล้ว · ซื้อ
   (วันเริ่มต้องหลังวันเริ่มของลูกค้า 1)
2. **เครื่อง A · แก้รายการลูกค้า 1**: ผล = ซื้อ · หมายเหตุ "สลับเครื่อง · ซื้อเครื่อง S/N … แทน"
   → กล่องต้องขึ้น "ไม่ใช่รายการล่าสุด → ไม่กระทบข้อมูลเครื่อง"
3. **เครื่อง B**: ปิดการทดลองแบบซื้อ หรือเพิ่มประวัติเอง (ลูกค้า 1 · จบแล้ว · ซื้อ)

ถ้าทำข้อ 2 ก่อนข้อ 1 กล่องจะขึ้น **สีแดง** เตือนว่าลูกค้าและวันส่งมอบของเครื่อง A จะถูกเปลี่ยน → เอาติ๊กออกได้

> ใช้ผล **"ซื้อ"** กับลูกค้าที่ซื้อเครื่องอื่นแทน (ไม่ใช่ "ไม่ซื้อ") ไม่งั้น Dashboard จะนับเป็นลูกค้าที่ไม่ซื้อ

## Service Tracker: การคำนวณวันนัด PM (อ้างอิง)

- รอบละ 4 เดือน · ปีละ 3 รอบ
- วันนัดแรก: วันส่งมอบ +4 / +8 / +12 เดือน
- ปิดงาน PM1 วันที่ X → PM2 = X+4 · PM3 = X+8 เดือน · ปิด PM2 วันที่ Y → PM3 = Y+4 เดือน
- Admin แก้วันนัดได้เฉพาะรอบที่ถึงคิว รอบถัดไปเลื่อนตาม +4 เดือน
- ต่ออายุสัญญา: PM1 = วันเริ่มสัญญา +4 เดือน (ล้าง PM2/PM3)
- สถานะ: เลยกำหนด (เลยวันนัด) · ใกล้กำหนด (ภายใน 7 วัน) · ตามแผน · ทำแล้ว
- บวกเดือนแบบตรง: ปลายเดือนอาจล้นไปต้นเดือนถัดไป (เช่น 30 ต.ค. +4 เดือน = 2 มี.ค.)

- **ยังค้าง:** ย้ายรหัส Admin ไปเก็บใน Script Properties + เปลี่ยนรหัสใหม่ (รหัสเดียวกันใช้กับ Color Sorter / C2-Loop)

## Deploy

### หน้าเว็บ
1. แก้ไฟล์แล้วเปลี่ยนเลข `?v=` ใน `index.html`
2. commit + push ขึ้น GitHub → รีเฟรช (Ctrl+Shift+R)

### Code.gs (Apps Script)
1. เปิด `Desktop\C2TECH Http\Service Tracker\Code.gs` → Ctrl+A → Ctrl+C
2. Apps Script → ไฟล์ **Code.gs** → Ctrl+A → Ctrl+V → 💾 Save (ไม่แตะ AddMachine.gs)
3. **Deploy → Manage deployments** → ✏️ → Version: **New version** → **Deploy** (URL เดิม)
